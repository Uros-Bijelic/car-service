# Plan: Shared header with a light/dark theme switch (apps/web)

## Context

You want a header with a theme switch (a shadcn `Switch`), and the theme must apply across the whole app. Current state:

- `next-themes@0.4.6` is installed and `components/ui/sonner.tsx` already calls `useTheme()`, but **no `ThemeProvider` is mounted**, so the theme never changes.
- `index.css` defines dark tokens under a **`.dark` class** (`@custom-variant dark (&:is(.dark *))`). `next-themes` sets a `data-theme` attribute by default, so it must be configured with `attribute="class"`.
- There is no `switch` component in `components/ui` yet. `radix-ui@1.4.3` already includes `@radix-ui/react-switch`, so no new dependency is needed.
- `layout/Header.tsx` is a shadcn demo dropdown with debug borders. It only renders on protected routes, through `AppLayout`.
- **Decision (yours): a shared header on every page.** It always shows the theme switch and shows the user menu only when logged in.

Result: one `ThemeProvider` at the root, a `ThemeToggle` (Sun · Switch · Moon) in a header that also renders on `/login` and `/register`, and the theme stored in localStorage without a light flash on reload.

## Step 1 – Add the shadcn Switch

From `apps/web`:

```bash
pnpm shadcn add switch
```

This creates `src/components/ui/switch.tsx`. It imports `{ Switch as SwitchPrimitive } from "radix-ui"`, which matches `button.tsx` and `dropdown-menu.tsx`. CLI output uses double quotes, like `dropdown-menu.tsx`. Reformat it with your editor's Prettier if you want it to match the repo style. Don't edit its internals. You can style it from the outside with `className`.

## Step 2 – Mount `ThemeProvider` at the root

In `src/providers/Providers.tsx`, wrap **everything**, including `Toaster`, because `sonner.tsx` reads `useTheme()` and sits outside `RouterProvider`:

```tsx
import { ThemeProvider } from 'next-themes';

<ThemeProvider
    attribute="class"              // REQUIRED: the CSS keys off `.dark`, not data-theme
    defaultTheme="system"          // first visit follows the OS
    enableSystem
    storageKey="car-service-theme" // localhost:5173 is shared by every Vite app you run
    disableTransitionOnChange      // avoids colors animating mid-switch
>
    <QueryClientProvider client={queryClient}>
        <AuthProvider>
            <RouterProvider router={router} />
            <Toaster ... />
        </AuthProvider>
    </QueryClientProvider>
</ThemeProvider>
```

Use the library component directly. A custom wrapper isn't needed. `next-themes` puts `light` or `dark` on `<html>` and sets `style.color-scheme`, so native scrollbars and inputs also follow the theme.

## Step 3 – Prevent the flash of the wrong theme (`index.html`)

`next-themes` renders an inline `<script>` from inside React. In a client-only Vite app that script never executes, so the class is only applied after React mounts. Dark-mode users would see a light flash on reload. Add a small blocking script to `<head>` that mirrors what `next-themes` does, using **the same `storageKey`**:

```html
<script>
    (function () {
        try {
            var t = localStorage.getItem('car-service-theme') || 'system';
            var dark =
                t === 'dark' ||
                (t === 'system' &&
                    matchMedia('(prefers-color-scheme: dark)').matches);
            var el = document.documentElement;
            el.classList.add(dark ? 'dark' : 'light');
            el.style.colorScheme = dark ? 'dark' : 'light';
        } catch (e) {}
    })();
</script>
```

(While you're in `index.html`, you could also change `<title>frontend</title>` to the app name.)

## Step 4 – `ThemeToggle` component

New file `src/components/common/ThemeToggle.tsx` (`components/common` holds shared app components such as `LoadingSpinner`). Core wiring:

```tsx
const { resolvedTheme, setTheme } = useTheme();
const isDark = resolvedTheme === 'dark';

<Switch
    checked={isDark}
    onCheckedChange={(checked) => setTheme(checked ? 'dark' : 'light')}
    aria-label="Toggle dark mode"
/>
```

Notes:
- Read **`resolvedTheme`**, not `theme`. On first visit `theme` is `'system'`, and `resolvedTheme` turns it into `'light'` or `'dark'`. Once the user flips the switch, the explicit choice is saved and replaces `'system'`.
- Lay it out as `SunIcon · Switch · MoonIcon` in a `flex items-center gap-2` row. `lucide-react` exports `SunIcon` and `MoonIcon` (the same `*Icon` naming `sonner.tsx` uses). Mark the icons `aria-hidden`, since the switch has its own `aria-label`.
- **No `mounted` guard is needed.** Tutorials add one for Next.js SSR hydration. Here `next-themes` reads localStorage and `matchMedia` synchronously on the first client render.
- React Compiler is on, so there's no need for `useCallback` around the handler.
- *(Optional polish)* Show the Sun or Moon icon inside the thumb by passing children or a class to the thumb. Get the basic version working first.

## Step 5 – Router: one root layout around both guards

In `src/router/Router.tsx`, `AppLayout` moves to the top so both protected and public pages get the header:

```tsx
export const router = createBrowserRouter([
    {
        element: <AppLayout />,
        children: [
            {
                element: <ProtectedRoute />,
                children: [{ path: '/', element: <Home /> }]
            },
            {
                element: <PublicRoute />,
                children: [
                    { path: '/login', element: <Login /> },
                    { path: '/register', element: <Register /> }
                ]
            }
        ]
    }
]);
```

`ProtectedRoute` and `PublicRoute` stay unchanged. Their `fullscreen` spinner is `fixed inset-0 z-50`, so it covers the header during the initial auth check, which is fine. `useAuth()` works inside `Header` because `AuthProvider` wraps `RouterProvider`.

## Step 6 – `AppLayout` cleanup

The current `w-7xl` is a fixed 80rem width and overflows on small screens. Remove the debug border too:

```tsx
<div className="flex min-h-dvh flex-col">
    <Header />
    <main className="mx-auto flex w-full max-w-7xl flex-1 flex-col">
        <Outlet />
    </main>
```

`flex flex-col` on `<main>` lets pages use `flex-1` to fill the space below the header (needed in Step 8).

## Step 7 – Rewrite `Header`

Structure:

```
<header sticky top-0 z-40 border-b bg-background/80 backdrop-blur>
  <div mx-auto max-w-7xl h-16 px-4 flex items-center justify-between>
    LEFT:  <Link to="/">Car Service</Link>   (font-heading, bold)
    RIGHT: <ThemeToggle />  {user && <UserMenu />}
  </div>
</header>
```

- Get `user` from `useAuth()` (`@/features/auth/hooks/use-auth`).
- **Use only theme tokens** (`bg-background`, `text-foreground`, `border-border`, `text-muted-foreground`), not fixed colors like `border-red-500`, so the header flips with the theme automatically. The `z-40` keeps it under the spinner overlay (`z-50`) and Radix portals.
- **UserMenu**: inline in `Header.tsx` or in its own `src/layout/UserMenu.tsx`. Replace the demo dropdown contents:
  - The trigger is currently empty. Use `<DropdownMenuTrigger asChild><Button variant="ghost" size="icon" aria-label="Open user menu"><UserIcon /></Button></DropdownMenuTrigger>`.
  - Content: `DropdownMenuLabel` with `user.username` and `user.email` (in `muted-foreground`), a `DropdownMenuSeparator`, then a **Log out** `DropdownMenuItem` that calls `useLogoutUser().mutate()` and is disabled while `isPending`. Set `align="end"` on `DropdownMenuContent`, since the menu sits at the right edge.
  - `useLogoutUser` uses `useNavigate`. That's fine here, because `Header` renders inside the router.
- Trim the unused dropdown imports.

## Step 8 – Auth pages fit under the header

In `Login.tsx` and `Register.tsx`, change the section from `h-dvh flex-center px-4` to `flex-1 flex-center px-4 py-8`. Otherwise header plus `h-dvh` is taller than the viewport and the page scrolls.

## Step 9 – *(Optional)* Remove the Logout button from `Home`

Once Log out is in the user menu, `Home.tsx` no longer needs its own button and `useLogoutUser` import.

## Gotchas checklist

- `attribute="class"` is missing → nothing changes visually (the most common mistake).
- `storageKey` must be identical in `Providers.tsx` and the `index.html` script.
- Read `resolvedTheme` for the switch state, not `theme`.
- Radix portal content (dropdown, toasts) renders into `<body>`, which is inside `<html class="dark">`, so it follows the theme automatically.
- Imports in `apps/web` use the `@/` alias (no `.js` extension needed, unlike the API).
